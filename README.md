# نظام ميسرة أحمد — MIYSARA Ahmed

نظام متكامل لإدارة محلات الملابس: إدارة المخازن ونقاط البيع POS والكاشير والمنتجات والفواتير والشفتات والتقارير والمستخدمين والصلاحيات — بواجهة عربية RTL كاملة.

## المكونات

- **server/** — API (Node.js + Express + better-sqlite3/SQLite)
- **client/** — واجهة React (Vite + TailwindCSS)
- **old_data/** — أدوات استخراج وترحيل بيانات النظام القديم (ESClothes، SQL Server 2000)

## التشغيل

### المتطلبات
- Node.js 20+
- (اختياري) Python 3 لاستخراج البيانات القديمة

### إعداد قاعدة البيانات
```bash
cd server && npm install
npm run seed        # ينشئ القاعدة وينشئ المستخدم الإداري الافتراضي
```
الخصائص المهمة:
- `PORT` (افتراضي 12001)
- `JWT_SECRET` — غيّره بقوة في الإنتاج
- `ADMIN_PASSWORD` — كلمة مرور الإدمن الافتراضية عند الـ seed

### تشغيل الـ API
```bash
cd server && npm start        # http://localhost:12001
```

### تشغيل الواجهة (وضع التطوير)
```bash
cd client && npm install
npm run dev                     # http://localhost:12000 — يوجّه /api إلى 12001
```

### تشغيل الواجهة (إنتاج)
```bash
cd client && npm run build      # ينتج في client/dist
```
يمكن خدمة الملفات المبنية بأي خادم ثابت، مع توجيه `/api` إلى خادم الـ API.

## أول استخدام

1. سجل الدخول بالـ Super Admin الافتراضي: `admin / admin123` — غيّره فورًا من صفحة المستخدمون.
2. من "الإعدادات" أنشئ مخزنًا رئيسيًا ونقطة بيع واحدة على الأقل.
3. ارّبط المستخدمين بالمخزن ونقاط البيع من صفحة المستخدمون والأدوار.
4. أضف التصنيفات/المواسم/الموردين/المصنعين من "البيانات الأساسية".
5. أنشئ المنتجات ومتغيراتها (SKU/BarCode/مقاس/لون/سعر شراء وبيع) من "المنتجات".
6. اِستلم بضاعة للمخزن من "الاستلام" (يدعم باركود)، أو نفّذ جردًا ابتدائيًا.
7. حوّل الرصيد من المخزن إلى نقطة البيع من "التحويلات".
8. نقطة البيع: امسح بالباركود أو ابحث، وبيع. الفاتورة تُعاد للتحديد بعد الطباعة.
9. كل كاشير يفتح الشفت ويدخل الفكة، ثم ينهيه بإدخال النقد الفعلي لإظهار فرق الدرج.
10. تقارير المبيعات/المخزون/الأرباح/الكاشير من "التقارير ولوحة التحكم".

## الصلاحيات

ترتيب نمطي: `مجال.فعل` — مثل `products.create`, `invoices.edit`, `pos.sell`, `inventory.transfer`. يُطبَّق على كل طلب في الـ API، مع الحفاظ في الـ Audit Log لعمليات مثل استلام، تحويل، إغلاق شفت، تعديل فاتورة، مرتجع…

الأدوار الافتراضية في الـ seed:
- Super Admin — كل شيء
- System Manager — إدارة المخازن والمنتجات والتقارير
- Warehouse Manager / Warehouse User — عمليات المخزون
- POS Manager — متابعة والتقارير على نقاط البيع
- Cashier — البيع والشفت فقط، بلا أسعار تكلفة أو أرباح

## ترحيل البيانات القديمة

ملف النسخة القديمة (MTF/SQL Server 2000) حُلل واستُخرج:

- `old_data/extract2.py` — يحلل نظام (sysobjects/syscolumns) من الصفحات الثابتة 8KB
- `old_data/extract3.py` — يقرأ صفوف الجداول وتشفيرها
- `old_data/extract_all.py` — يستخرج الكتالوج + المخزون
- `old_data/migrate.js` — يبعد البيانات إلى SQLite الجديد (تصنيفات، منتجات، متغيرات، باركود، أسعار، رصيد)

النتيجة: 7,050 منتجًا + 6,840 متغيرًا + ~595 ألف قطعة رصيد مُرحَّل.

## ملاحظات أمنية

- التحقق من المرة المدخلات (zod مبسّط داخلي) + قيود SQL CHECK/UNIQUE في قاعدة البيانات.
- منع SQL Injection بـ prepared statements حصرًا.
- Restriction: الكاشير حصر على نقطة البيع المفوضة له + إمكانية فصل المستخدم عن المخازن.
- كلمة المرور: bcrypt.
- Helmet + CORS + rate-limit.
